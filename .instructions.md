# Pet E-Commerce Project Instructions for AI

## Project Overview
This is a **Pet E-Commerce Next.js Application** with user authentication, product catalog, and customer dashboard.

### Tech Stack
- **Framework**: Next.js 16.1.6 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS 4
- **Authentication**: Firebase Authentication
- **UI Components**: React Icons, Embla Carousel
- **HTTP Client**: Axios
- **Linting**: ESLint 9

### Coding Patterns & Conventions

#### 1. Feature-Based Structure
- Each feature lives in `src/features/[featureName]/`
- Structure: `components/` → UI, `servers/` → server actions, `index.ts` → exports
- Example: Guest login feature
  ```
  features/guest/login/
  ├── components/login-form.tsx
  ├── servers/login.ts
  └── index.ts
  ```

#### 2. Server Actions Pattern
- Located in `servers/` folders within features
- Use "use server" directive
- Files in `servers/` handle backend logic (Firebase auth, API calls)
- Example (`features/guest/login/servers/login.ts`):
  ```typescript
  "use server"
  import { loginWithEmail } from "@/integrations/firebase"
  
  export async function loginAction(email: string, password: string) {
    // Server-side logic here
  }
  ```

#### 3. Component Organization
- UI components in `components/` folder within feature
- Use TypeScript interfaces for props
- Keep components in subfolders using index.ts for exports
- Global reusable components in `src/components/`

#### 4. Types & Interfaces
- Store shared types in `src/types/`
- Current types: `UserInfo`, `Category`, `Subcategory`
- Follow naming convention: Use descriptive names, avoid `any`

#### 5. Firebase Integration
- All Firebase setup in `src/integrations/firebase.ts`
- Available exports: `auth`, `loginWithEmail`, `createUserWithEmailAndPassword`, etc.
- OAuth providers configured: Google, Facebook
- Environment variables used: `NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_APP_ID`

## Code Style Guidelines

### TypeScript & Naming
- Use PascalCase for components: `LoginForm`, `ProductCard`
- Use camelCase for functions/variables: `loginAction`, `handleSubmit`
- Use UPPER_SNAKE_CASE for constants
- Always define interfaces for props and data structures
- Avoid `any` type - use specific types

### File Naming
- React components: PascalCase (`.tsx`): `ProductCard.tsx`
- Server actions: camelCase (`.ts`): `login.ts`, `logout.ts`
- Index files for barrel exports: `index.ts`

### Imports
- Use absolute imports with `@/` alias
- Organize imports: React → Next → Types → Components → Utils
- Use barrel exports (index.ts) for feature modules

## Adding New Features

### Step 1: Create Feature Folder Structure
```
src/features/guest/newFeature/
├── components/
│   └── index.ts
├── servers/
│   └── action.ts
└── index.ts
```

### Step 2: Create Components
```typescript
// components/SomeComponent.tsx
import { ReactNode } from "react";

interface Props {
  title: string;
  children?: ReactNode;
}

export default function SomeComponent({ title, children }: Props) {
  return <div>{title}</div>;
}
```

### Step 3: Create Server Actions
```typescript
// servers/action.ts
"use server"
import { auth } from "@/integrations/firebase"

export async function someAction(data: string) {
  // Server logic here
}
```

### Step 4: Create Barrel Exports
```typescript
// index.ts
export * from "./components"
export * from "./servers"
```

## Important Notes

### Authentication Flow
1. Firebase Authentication for user login/register
2. Server actions handle Auth operations
3. User state synced via `userSync.ts`
4. Guest flow in `features/guest/`, authenticated flow in `features/customer/`

### Data Fetching
- Use Axios for API calls
- Server actions for Firebase operations
- Categories fetched via `features/guest/category/servers/category.ts`

### Styling
- Tailwind CSS (v4) with @tailwindcss/postcss
- PostCSS configured via `postcss.config.mjs`
- Global styles in `app/globals.css`
