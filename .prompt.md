# Code Generation Guidelines for Pet E-Commerce

## When Creating Components

Always follow this template:
```typescript
// Import necessary dependencies
import { ReactNode } from 'react';

// Define clear prop interface
interface ComponentNameProps {
  title: string;
  onAction?: () => void;
  children?: ReactNode;
}

// Functional component with TypeScript
export default function ComponentName({
  title,
  onAction,
  children,
}: ComponentNameProps) {
  return (
    <div className="flex items-center justify-center">
      {/* Content here */}
    </div>
  );
}
```

## When Creating Server Actions

Always include the directive and proper typing:
```typescript
'use server'

import { auth } from '@/integrations/firebase';
import type { SomeType } from '@/types';

export async function actionName(data: string): Promise<{ success: boolean; message: string }> {
  try {
    // Logic here
    return { success: true, message: 'Success' };
  } catch (error) {
    console.error('Error:', error);
    return { success: false, message: 'Error occurred' };
  }
}
```

## Error Handling

### Server Actions
```typescript
'use server'

export async function safeAction(input: string) {
  try {
    // Validate input
    if (!input || input.trim() === '') {
      return { success: false, message: 'Input required' };
    }

    // Perform action
    const result = await someAsyncOperation(input);
    
    return { success: true, data: result };
  } catch (error) {
    const message = error instanceof Error ? error.message : 'Unknown error';
    console.error('Action error:', message);
    return { success: false, message };
  }
}
```

## Do's and Don'ts

### ✅ DO
- Use TypeScript interfaces for all props
- Place server logic in `servers/` folders
- Use absolute imports with `@/`
- Keep components pure and focused
- Export components via index.ts
- Use "use server" directive in server files
- Handle errors explicitly

### ❌ DON'T
- Don't use `any` type
- Don't put server logic in components
- Don't use relative imports for distant files
- Don't create deeply nested component files
- Don't forget error handling in server actions
- Don't leave console.log in production code
- Don't create components without proper TypeScript interfaces

## Testing Considerations

When code generation includes logic, consider:
- Input validation
- Error conditions
- Edge cases for authentication
- Type safety throughout

## Performance Tips

- Use React.memo for frequently rendered components
- Lazy load heavy components with React.lazy
- Cache Firebase auth state
- Debounce Axios requests when needed

## Accessibility

- Add alt text to images
- Use semantic HTML elements
- Ensure form labels are associated with inputs
- Test keyboard navigation where applicable
